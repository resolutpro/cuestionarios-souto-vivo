Quiero que diseñes y especifiques una aplicación web para registrar, digitalizar e integrar respuestas del “CUESTIONARIO DE INTERÉS – PROYECTO SOUTO VIVO (Participación en fincas agroforestales piloto)”. El sistema debe admitir tres vías de entrada (web, OCR desde escaneos, integración con Google Forms) y un panel de consulta con filtros. Además, debe contemplar un flujo de validación humana para los datos extraídos por OCR antes de considerarlos definitivos.
1) Objetivo del sistema
Centralizar todas las respuestas al cuestionario en una base de datos única, permitiendo:
Alta manual desde web (formulario digital).


Carga masiva de cuestionarios escaneados + OCR + revisión/validación.


Sincronización automática con respuestas de Google Forms (mismo cuestionario).


Consulta y análisis mediante un panel con filtros y exportación.


2) Roles y permisos (RBAC)
usuario admin creado por defecto con creddeciales en .secrets. al entrar lo primero que se verá de la web será el login
3) Canales de entrada (3 modos)
(A) Formulario web (captura directa)
Implementar un formulario web que replique exactamente las secciones y campos del cuestionario.


Validación de campos obligatorios.


Guardado como “submisión” (submission) con estado:


BORRADOR (si se guarda parcialmente),


ENVIADO (si se completa),


APROBADO (si requiere revisión interna opcional),


RECHAZADO (si se anula).


(B) Subida de PDFs escaneados (uno o varios) + OCR + propuesta + validación
Pantalla para subir uno o varios archivos (PDF/JPG/PNG).


Crear un job de OCR por archivo (o por página).


Extraer campos del cuestionario mediante OCR y generar una “propuesta de datos” (candidate extraction):


Guardar para cada campo: valor propuesto, confianza OCR, coordenadas/fragmento, y referencia al archivo/página.


Interfaz de validación:


Mostrar el PDF/imagen y, en paralelo, los campos extraídos.


Permitir editar valores, marcar como correctos/incorrectos, dejar comentarios.


Acción final: “Aprobar” (convierte propuesta en registro definitivo) o “Rechazar” (mantiene el archivo pero no crea/actualiza el registro).


Estados del OCR:


PENDIENTE_OCR, OCR_COMPLETADO, PENDIENTE_REVISION, APROBADO, RECHAZADO.


Debe existir detección de duplicados (por ejemplo, combinación de nombre+teléfono+localidad+referencias catastrales) y aviso al revisor.


(C) Integración automática con Google Forms (mismo cuestionario)
Conectar a un Google Form equivalente al cuestionario.


Ingesta continua: nuevas respuestas deben crear registros automáticamente en la BD.


Debe existir un mapeo de campos Google Forms → campos internos.


Debe manejar:


Actualizaciones si se reenvía una respuesta (según responseId o timestamp),


Duplicados,


Campos “otros (especificar)” como textos libres asociados.


Registrar fuente del dato: WEB, OCR, GOOGLE_FORMS.
